# The China AI Registry — データ定義

このファイルは、`data/` にある台帳のデータが何を、どの規律で記録しているかを定める。運用の手順は `docs/UPDATE_RUNBOOK.md` にある。

**制定**：2026-11-22（v1.3・附件1〜14）

---

## 1. 何を記録するか（母集団）

中国の国家互联网信息办公室（CAC）が公告した「生成式人工智能服务已备案（和已登记）信息」の**附件に記載された、すべての行**を記録する。

- 母集団を決めるのはCACである。著者は行を選ばない。連結した附件の行は、例外なくすべて収める
- 附件のPDFに書かれている行だけを収める。報道、地方の網信部門の発表、企業の発表からは行を起こさない
- 附件は累計ではなく差分である（本文第1章）。附件1から順に連結して、はじめて全数になる
- 序号を持たない公告（例：2026年9月23日の端末側3件の公告。内訳は画像）からは行を起こさない。`registry.json` の `separate_notices` に記録し、後の附件に序号つきで載った時点で、その附件の行として収める

## 2. 表（序号の系列ごとに1つ）

**原則：1つの序号の系列を、1つの表にする。** CACが新しい系列の表を附件に加えた場合は、ここと `registry.json` の `tables` に定義を足してから連結する（定義にない表があると、スクリプトは止まる）。

| 表 | キー | IDの接頭辞 | 原表の表題 | 始まった附件 | 公告の累計に数える先 |
|---|---|---|---|---|---|
| 備案 | `filings` | F | 生成式人工智能服务已备案信息 | 附件1 | 備案 |
| 端末側の備案 | `filings_on_device` | D | 提供手机端侧生成式人工智能服务已备案信息 | 附件13 | 備案 |
| 擬人化された対話の備案 | `filings_anthropomorphic` | A | 拟人化互动服务场景生成式人工智能服务已备案信息 | 附件14 | 備案 |
| 登記 | `registrations` | R | 生成式人工智能服务已登记信息 | 附件2 | 登記 |
| 備案の変更 | `filing_changes` | C | 生成式人工智能服务已备案变更信息 | 附件14 | なし |

- 備案の3つの表は序号がそれぞれ1から始まる別の系列だが、CACの公告本文の「累計の備案」は3つの合計である（附件14の時点で 1,234＋10＋1＝1,245）。登記の系列とは**足さない**
- 備案の変更は、既に備案されたサービスの情報（単位の名称など）が変わったことの記録である。**元の備案の行は書き換えず、変更をこの表に追記する。** 変更の行は `target_id` で元の行を指す
- 登記は附件2（2024年8月）から始まる

## 3. 転記の規律

1. **原表の列位置のまま写す。** 列がずれている行（例：序号340〜345）も補正しない。補正は解釈であり、転記ではない
2. **文字を足さない、消さない、置き換えない。** 空白は、PDFに字形として存在するものだけを空白とする（字と字の隙間は空白としない）。取り除くのは次の二つだけである
   - セル内の改行（PDFの折り返しで生じたもの）
   - セルの両端の空白
   セルの内部の空白（半角・全角・連続した空白・ノーブレークスペース）は残す。折り返し位置に空白の字形がある場合は、その空白も残す
3. **誤字、混入、表記の揺れを直さない。** 気づいたものは `observations` に記録する（第5節）
4. **翻訳しない。** 値は簡体字のまま記録する。日本語・英語の名称は本文が担う
5. **解釈を伴う欄を置かない。** 業種、法人の名寄せ、外資かどうか、成否の評価は、データの層に入れない。これらは本文（分析の層）で、使ったデータの版を示して行う

転記は `scripts/extract_attachment.py` が行う。同じPDFと同じ pdfplumber の版（0.11.10）からは、同じ出力が得られる。

## 4. 欄の定義

### 4-1. 行（`filings`・`registrations` 共通）

| キー | 意味 | 原表の見出し（備案／登記） | 規律 |
|---|---|---|---|
| `id` | 行のID | なし | 備案は `F`＋序号4桁、登記は `R`＋序号4桁 |
| `seq` | 序号 | 序号 | 原表の数字 |
| `jurisdiction` | 属地 | 属地 | 原表のまま。「国资委」も属地として扱う |
| `name` | 名称 | 模型名称・大模型名称／应用/功能名称 | 原表のまま |
| `entity` | 単位 | 备案单位／登记单位 | 原表のまま |
| `number` | 番号 | 备案号・备案编号／上线编号 | 原表のまま |
| `date_raw` | 時間（原表の文字列） | 备案时间／登记时间 | 「（补登）」などの注記を含めて原表のまま |
| `date` | 日付 | なし | `date_raw` の日付部分を YYYY-MM-DD に書き換えたもの |
| `date_note` | 日付の注記 | なし | `date_raw` の日付の後ろにある文字列（例：「（补登）」）。なければ `null` |
| `source.attachment` | 附件番号 | なし | CACのハブページでの附件の番号 |
| `source.page` | ページ | なし | PDFのページ番号（1から） |
| `source.order` | 出現順 | なし | その附件のその表の中での、原表の並び順（1から） |
| `observations` | 観察 | なし | 第5節のコードの配列。値は変えていない |
| `scenario` | 適用場景 | 适用场景 | 端末側・擬人化された対話の備案と、備案の変更の表にだけある。原表のまま（「/」を含む） |
| `changed_raw`・`changed`・`changed_note` | 変更時間 | 变更时间 | 備案の変更の表にだけある。`date_raw`・`date`・`date_note` と同じ規律 |
| `target_id` | 変更の対象の行 | なし | 備案の変更の表にだけある。番号が完全に一致する備案の行（F・D・A）のID。一致がなければ `null` |
| `corrections` | 訂正 | なし | 転記の誤りを見つけたときにだけ置く配列。各項目に日付・欄・PDFの字のとおりの値（`as_printed`）・理由を書く。元の値は書き換えない（`UPDATE_RUNBOOK.md` 第4節） |

附件6以降の登記の表では、原表の見出しが備案の表と同じ文言（大模型名称・备案单位・备案编号・备案时间）になっている。キーは列の位置で統一し、附件ごとの原表の見出しは `sources[].headers` に記録する。

### 4-2. 出典（`sources`）

附件1件につき1項目を置く。まだ連結していない附件も、存在を確認した時点で項目を置く。

| キー | 意味 |
|---|---|
| `attachment` | 附件番号 |
| `status` | `connected`（連結済み）／`not_connected`（未連結） |
| `hub_url`・`hub_label` | ハブページのURLと、そこでの附件の表題 |
| `pdf_title` | PDFの中に印字された表題（テキストとして取り出せた範囲）。取り出せない場合は `null` とし、`pdf_title_note` に書く |
| `file_name`・`file_sha256`・`pages` | 転記に使ったPDFのファイル名・SHA-256・ページ数。読者は同じファイルかどうかをハッシュで確かめられる |
| `retrieved` | PDFを取得した日 |
| `extractor` | 転記に使った道具と版、設定 |
| `headers` | 附件ごとの原表の見出し（備案・登記） |
| `notice` | 公告本文のURL・日付・表題と、本文に書かれた件数（`stated`）。CACの公告ページで確認したものだけを書く。報道の数字は書かない |
| `notice.stated` | 公告本文の件数。新規の備案（`new_filings`、3つの備案の表の合計）・新規の登記・累計・基準日のほか、本文に内訳があれば `new_filings_on_device`・`new_filings_anthropomorphic`・`changed_filings` |
| `tables` | 表ごとの、連結した行数と序号の範囲 |
| `observations` | 附件単位の観察（第5節） |

PDFそのものはリポジトリに含めない。原本はCACのハブページにある。

## 5. 観察コード

観察は、原表について気づいたことの記録である。**観察があっても値は変えない。** 行の観察は `register_attachment.py` が連結のときに規則で付け、以後変えない。

| コード | 付ける条件 |
|---|---|
| `SEQ_OUT_OF_ORDER` | 原表の並びで、直前の行の序号＋1になっていない |
| `COLUMN_SWAP_SUSPECTED` | 名称が組織名の語尾（公司・研究院・研究所・大学・学院・集团・中心・医院・委员会・实验室）で終わり、単位がそうでない |
| `LEADING_CHAR_SUSPECTED` | 単位が「司」で始まる（「司法」を除く） |
| `WHITESPACE_IN_NUMBER` | 番号の内部に空白がある |
| `LATIN_WRAP_UNRESOLVED` | 原表のセルが英数字の途中で折り返され、折り返し位置に空白の字形がない。空白を足さずに連結した |
| `PREFIX_VARIANT` | 番号の接頭辞（最初の「-」より前）が、連結の時点で同じ属地の他の行のどれとも一致しない（大文字小文字は区別しない） |
| `TARGET_NOT_FOUND` | 備案の変更の行の番号と完全に一致する備案の行がない |
| `TARGET_AMBIGUOUS` | 備案の変更の行の番号と一致する備案の行が複数ある |

附件単位の観察：

| コード | 付ける条件 |
|---|---|
| `COUNT_MISMATCH_WITH_NOTICE` | 附件の行数・最後の序号が、公告本文の件数と合わない。どちらも変えずに併記する |
| `SOURCE_FILE_CHANGED` | CACが同じ附件のPDFを差し替え、ハッシュが変わった。既存の行は書き換えず、差分を各行の `corrections` に記録する |

観察の規則は機械的なものであり、すべての異常を拾う保証はない。規則で拾えない誤りに気づいた場合は、`UPDATE_RUNBOOK.md` 第4節の訂正の手順に従う。

## 6. 検査

次のいずれかに当たると、スクリプトは何も書かずに止まる。

**連結のとき（`register_attachment.py`）**
- PDFのハッシュが、`sources` に先に書いたものと違う
- 定義にない表がある
- 附件の最初の序号が、その表の最後の序号の次でない
- 附件の中に欠番・重複がある
- 公告本文の件数（新規・累計・内訳）と附件の行数が合わず、その食い違いが `sources[].observations` に記録されていない
- 既に連結した附件を、もう一度連結しようとした

**生成のとき（`build_registry.py`）**
- 序号が1から欠番・重複なく続いていない
- `id` と序号が対応しない、または重複している
- 必須の欄（属地・名称・単位・番号・時間）が空
- `date`（備案の変更では `changed` も）が YYYY-MM-DD でない
- `target_id` が台帳にない行を指している
- 未定義の観察コードがある
- `corrections` の項目に日付・欄・`as_printed` が揃っていない
- 連結済みの附件の行数・序号の範囲が `sources` と合わない

## 7. ファイル

| ファイル | 種別 | 内容 |
|---|---|---|
| `data/registry.json` | 正本 | 定義・出典・全行。編集はスクリプトを通して行う |
| `data/filings.csv` | 派生 | 備案。UTF-8（BOM付き）。以下のCSVも同じ |
| `data/filings_on_device.csv` | 派生 | 端末側の備案 |
| `data/filings_anthropomorphic.csv` | 派生 | 擬人化された対話の備案 |
| `data/registrations.csv` | 派生 | 登記 |
| `data/filing_changes.csv` | 派生 | 備案の変更 |
| `data/sources.csv` | 派生 | 附件ごとの出典と連結の状態 |
| `scripts/extract_attachment.py` | 道具 | PDF → 一時ファイル（`data/staging/`、コミットしない） |
| `scripts/register_attachment.py` | 道具 | 一時ファイル → `registry.json` の末尾 |
| `scripts/build_registry.py` | 道具 | 検査と派生物の生成 |

CSVの `observations` の欄はコードを、`corrections` の欄は「日付:欄」を、それぞれ `;` で区切って並べる。

## 8. このデータが言えないこと

- 備案は「登録した」以上の意味を持たない。名簿に載っている実装が成功しているかどうかは、このデータからは分からない
- 備案の件数は社数ではない。同じ法人が複数の行を持ち、同じブランドが別の法人名義で登録されている。法人を名寄せする列はCACの表にない
- 対象は、当局が「世論属性または社会動員能力を有する」と判定した範囲のサービスであり、中国に存在するすべてのAIモデルではない
